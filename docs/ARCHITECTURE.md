## 1. Overview

Prax RAG is an enterprise Retrieval-Augmented Generation service. It ingests
documents, stores their embeddings in **PostgreSQL + pgvector**, and answers
questions by retrieving relevant chunks and generating a grounded response with
**Vertex AI Gemini**. Embeddings (for both documents and queries) are produced
by **Vertex AI text-embedding** models.

A **Streamlit chatbot** (`ui/`) is an optional presentation layer that calls the
API over HTTP: a sidebar manages the knowledge base (ingest/list/delete/reset)
and a chat window streams grounded answers via the `/query/stream` SSE endpoint.

### Design principles
- **Layered / clean architecture** — API, service, repository, and data layers
  are separated so each can evolve or be tested independently.
- **Dependency inversion at the edges** — Vertex and Postgres are isolated
  behind thin service/repository wrappers.
- **Config-driven** — all environment-specific values come from settings, never
  hard-coded in business logic.
- **Grounded generation** — the LLM is constrained to answer from retrieved
  context and cite sources.

## 3. Request flows

### Ingestion (`POST /ingest`, `POST /ingest/file`)
1. `loaders.extract_text` performs **layout-aware parsing** — PDFs go through
   PyMuPDF4LLM (multi-column reading order, heading levels, Markdown tables) and
   DOCX preserves heading styles + tables — producing structured Markdown.
2. `chunking.split_text` is **heading-aware**: it segments by Markdown headings
   and prefixes each chunk with its section breadcrumb (e.g. "Report > Revenue")
   before size-packing with overlap.
3. `EmbeddingService.embed_documents` calls Vertex (`RETRIEVAL_DOCUMENT`).
4. `VectorStore.add_document` persists the `Document` + `Chunk` rows (with vectors)
   in one transaction.

### Query (`POST /query`)
1. `EmbeddingService.embed_query` embeds the question (`RETRIEVAL_QUERY`).
2. `VectorStore.similarity_search` runs a pgvector **cosine-distance** nearest
   neighbour search for the top-k chunks.
3. `RAGService` assembles numbered context blocks.
4. `LLMService.generate` calls Vertex Gemini with a system instruction that
   forces context-only, cited answers.
5. The answer + ranked sources (with similarity scores) are returned.

## 4. Data model

- **Document** — `id`, `source`, `title`, `created_at`; one-to-many to chunks.
- **Chunk** — `id`, `document_id`, `chunk_index`, `content`, `embedding
  Vector(EMBEDDING_DIM)`, `created_at`.
- Similarity uses `Chunk.embedding.cosine_distance(...)`. For large corpora add
  an HNSW index on `embedding`.

## 9. Infrastructure

- **pgvector** runs via `docker-compose.yml` (`pgvector/pgvector:pg17`) exposed
  on host port `5433`. `sql/init.sql` enables the `vector` extension; the app
  also ensures it on startup (`init_db`).
- The Vertex client is a cached singleton (`app/core/vertex_client.py`) created
  with `vertexai=True` and the configured project/location.

## 10. Extending the system

| Goal | Where to change |
|---|---|
| New file format (e.g. HTML) | `app/services/loaders.py` |
| Different chunking strategy | `app/services/chunking.py` |
| Swap embedding/LLM model | `.env` (`EMBEDDING_MODEL`, `LLM_MODEL`) |
| New retrieval logic (filters, re-rank) | `app/repositories/vector_store.py`, `app/services/rag.py` |
| New endpoint | `app/api/routes/`, wire in `app/main.py` |
